## Scope (as planned, Pass 4 micro-plan)

Add `digestPreferences` and `digestSends` tables per `notes.md`'s Pass 2 data model.
`digestPreferences`: `userId`, `enabled`, `dayOfWeek`, `updatedAt`. `digestSends`: `id`,
`userId`, `sentAt`, `itemCount`, `status`.

- new migration under `src/db/migrations/`

## Acceptance (as planned)

Migration applies cleanly against the dev database; no existing tables affected.

## Re-spec — what actually shipped

Diverged from the plan above: added a `timezone` column (IANA tz name, e.g.
`"America/Denver"`) to `digestPreferences` that wasn't in the original Pass-2 schema. During
the Pass-4 micro-plan it became clear that `dayOfWeek` alone is ambiguous across timezones —
"Monday" at UTC midnight is still Sunday evening for half the user base. Decided to store
timezone per-user now rather than defer it, since retrofitting a nullable column onto a live
table later is strictly more annoying than adding it up front while the table is brand new and
empty. Everything else shipped as planned.
