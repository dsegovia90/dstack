# D3 — Digest content builder

**Status:** done · **Phase:** 2 · **Blocked-by:** D1 · **Blocks:** D4, D5

## Scope (as planned, Pass 4 micro-plan)

`digest/content.ts` — `buildDigestContent(userId, since)` querying saved items since the last
send, chronological, capped at a sane max count. Email template rendering the result.

## Files

- `src/digest/content.ts`
- `src/digest/templates/weekly-digest.tsx` (or equivalent)

## Acceptance (as planned)

Given a user with saved items in the last 7 days, `buildDigestContent` returns a correctly
ordered, capped list; the template renders it into a sendable email body.

## Re-spec — what actually shipped

Two divergences from plan, both recorded here as part of closing this ticket:

1. **Dropped "highlight top item."** Pass 2's architecture prose mentioned it as a stretch idea
   in passing (not actually in the groomed ticket scope above) — caught during implementation
   as scope creep and explicitly *not* built, consistent with Pass 1's "no personalized ranking
   in v1" call. Noted here so a future project revisiting this doesn't wonder whether it was
   forgotten vs. deliberately cut — it was deliberately cut.
2. **Absorbed finding `email-deliverability-review`** (see `findings/email-deliverability-review.md`):
   a review surfaced that the template wasn't setting a `Reply-To` header, which some providers'
   spam filters weight heavily for bulk-looking mail. Folded directly into this ticket rather
   than spawning a separate one, since it's a one-line addition to the same template this
   ticket already owns.
